# ModAVDManager v0.2.0

- `ModAVD.exe`：`c248eb67641387faa789a5cbe580d0c94c6f89a5a6075ff0b734afad15ba7868`
- `tools/modavd.exe`：`38ca4270622de354bf99c9a704dd69100ce8a7b23d67047c3a8325f01ef37aa6`

## 新增

- **新建实例时在后台做完初始化**：`create`（命令行、MCP、管理器）建完文件后，在后台无头开机一次，做完首次初始化、宿主输入法和执行桥，先 sync 再正常关机，才算新建完成。之后第一次开机和平常一样快。
  - 新建中，`status` 和 `busy` 都是 `creating`，这时开机、修改、删除都会提示实例忙。
  - 失败或超时记为 `create_failed`，`creation_error` 写原因。用 `create --resume N` 重做初始化，或者删掉重建。
  - 管理器里的新建和「重试初始化」都在后台跑，卡片上有进度。
- **更新整个 ModAVD 包**：`modavd update [status|check|prepare|install|recover]`，和 AUTO-MAS 的「魔改 AVD 一键更新」做同一件事，共用 `<根>\.update\` 目录，哪边更新到一半，另一边都能接着补完或退回。
  - 来源在管理器「设置」里选：GitHub，或者 Mirror 酱（填了 CDK 才能下载，能拿增量包）。CDK 加密保存，不进日志。
  - 现在由 AUTO-MAS 调用命令行发起更新，管理器里的「更新」按钮暂时不可用。
  - 加了 HTTPS 下载，`modavd.exe` 从约 4.9 MB 增大到约 8.3 MB。
- `info`、`list`、`status` 新增字段：`bridge`（`off`、`pending`、`installed`、`unknown`）、`started_at_ms`、`creation`、`creation_error`、`creation_log`。

## 修复

- 执行桥：装、卸期间持有实例锁（`busy` 为 `bridging`）；修好 `bridge install` 的回归；状态只问已经开完机的客体。
- `start` 返回之前，确认 `/sdcard` 真能写进文件（最多再等 60 秒）。以前开机刚完成时，脚本马上往 `/sdcard` 写文件可能失败。
- 修复开机时的竞态，以及几个进程同时准备客体脚本时的共享冲突。
- 新建失败时的报错不再括号套括号；更新时按名字兜底找进程，不再把 `crashpad_handler` 算进去。

## 给调用方（AUTO-MAS）

- `--json` 的新字段都是加的，`protocol` 仍是 1。`busy` 多了 `bridging`、`creating`，`status` 多了 `creating`、`create_failed`；认不出的取值一律当忙处理。
- 新错误码 `update_unavailable`、`update_rejected`，退出码 9。
- 新建会多花几分钟，但有进度；之后的 `start` 不再做首次初始化，开机的超时可以收短。
- 客体脚本的头注释改了，AUTO-MAS `res/avd/guest/` 里的同名脚本要跟着改（只改注释）。

## 下载与核对

使用 Go 1.26.5、`GOTOOLCHAIN=local`，运行仓库中的 `build.ps1` 可以编出相同字节。单独下载包还包含 Go 许可原文和文件清单；请用附件 `SHA256SUMS.txt` 核对 zip 和解压出的两个 exe，例如在 PowerShell 里运行 `Get-FileHash .\ModAVDManager-0.2.0-win-x64.zip -Algorithm SHA256`。

单独下载的管理器不会自己更新，新版本要手动替换；ModAVD 包里的那份随 ModAVD 整包一起更新。单独使用时请给 `--root` 或设置 `MODAVD_ROOT`，否则会提示找不到 ModAVD 根目录。不要把单独下载的 zip 解压到 ModAVD 根目录覆盖整包中的文件。
